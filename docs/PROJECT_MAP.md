## Database tables (🔒 = encrypted column)

- `users`: One row per Telegram chat id. This is the identity everything hangs on.
- `accounts`: Your pipes: Cash, Bank, cards. Holds the balance.
- `categories`: Spending/income categories and monthly budgets.
- `merchants`: Who you paid, with a default category.
- `transactions`: Every expense, income and transfer. 🔒 description
- `subscriptions`: Recurring bills.
- `chat_messages`: What you and the bot said. 🔒 content
- `api_keys`: AI keys users added (and shared keys under `__shared__`). 🔒 encrypted_key

## Request tours

**A message becomes a transaction** (You send: Spent 200 on chai, 80 on auto yesterday)
1. `app/bot/telegram.py`: Telegram delivers the message to the bot.
2. `app/bot/main.py`: `handle_incoming` checks you are allowed, and that it is not a /command or a screen.
3. `app/bot/agent.py`: The agent runs. First it asks the rules to read the message.
4. `app/bot/nlu.py`: Rules find 2 items, the amounts, the category words and the date. No AI is used.
5. `app/services_ai/tool_client.py`: Each item becomes a tool call (`log_expense`), sent through the one tool door: plain Python, or the MCP server in demo mode.
6. `app/services_ai/mcp_server.py`: The tool itself: validates the arguments and calls the ledger.
7. `app/services/ledger.py`: The ledger validates and saves the transaction and updates the balance together.
8. `app/bot/replies.py`: A two-line reply is written, and an Undo button is attached.

**A question for the AI** (You send: Can I afford a 50000 laptop in 5 months?)
1. `app/bot/main.py`: Not a command, not a screen: it goes to the agent.
2. `app/bot/nlu.py`: Rules see a question, so nothing is logged.
3. `app/bot/orchestrator.py`: The multi-step helper starts (needs an AI key).
4. `app/services_ai/ai_gateway.py`: Picks your key (then shared, then server keys) and the best model.
5. `app/services_ai/mcp_server.py`: The AI calls `savings_plan` / `get_financial_snapshot`.
6. `app/services/analytics.py`: Real numbers from your last 90 days come back.
7. `app/bot/orchestrator.py`: The AI reads them and writes a short answer.

**/dashboard** (You send: /dashboard)
1. `app/bot/views.py`: Builds a private link, valid for 2 hours.
2. `app/web/tokens.py`: Signs the link (chat id + expiry) so it cannot be forged.
3. `app/web/dashboard.py`: Checks the signature, serves the page and the data.
4. `app/services/analytics.py`: Computes the same numbers the Telegram charts use.
5. `app/web/static/dashboard.js`: The browser draws 12 charts from that data.

**Importing a PhonePe PDF** (You send a statement PDF)
1. `app/bot/telegram.py`: Downloads the file (size and type checked).
2. `app/bot/main.py`: Starts the import flow and shows a preview.
3. `app/services_ai/transaction_parser.py`: Detects the format, reads rows with the statement's own dates, guesses categories.
4. `app/bot/main.py`: You tap Import: rows already in the ledger are skipped.
5. `app/services/ledger.py`: Each new row is saved with its real date.

**Adding an AI key, safely** (You send: /setkey AIza...)
1. `app/bot/keys.py`: Finds the provider from the key's shape.
2. `app/services_ai/ai_gateway.py`: Tests the key live with a real model. Only a working key is saved.
3. `app/crypto.py`: The key is encrypted with its own derived key.
4. `app/models.py`: Stored in `api_keys.encrypted_key`.
5. `app/bot/telegram.py`: Your message is deleted from the chat.
